# Decisions taken where the spec was silent

Each line: the choice, and the one-line reason.

| # | Decision | Reason |
|---|---|---|
| D-01 | Hand-rolled shadcn-style primitives in `components/ui` instead of running the shadcn CLI | The CLI needs interactive prompts and network; hand-rolled Tailwind primitives are smaller, deterministic and have no install step that can fail on Vercel. |
| D-02 | SheetJS `xlsx@0.20.3` installed from a **vendored tarball** in `vendor/` rather than the npm registry copy | The registry copy is pinned at 0.18.5 and carries CVE-2023-30533 (prototype pollution) and CVE-2024-22363 (ReDoS). 0.20.3 is the patched official release. Vendoring means the Vercel build needs no network fetch. |
| D-03 | Pinned Gemini model is `gemini-3.8-flash` | `ListModels` on the supplied key shows `gemini-2.5-flash` returns HTTP 404 "no longer available to new users"; `gemini-3.8-flash` is the newest **stable** (non-preview, non-image, non-tts) model whose name contains `flash` and which answered a live `generateContent` probe. The spec's fallback chain is kept below it. |
| D-04 | Brand name defaults to **Kavi Retail**, editable in Workspace Settings | Chosen by the operator; an invented name avoids implying a real company. Stored on the policy profile so it is a one-field change. |
| D-05 | Light theme forced; the scaffold's `prefers-color-scheme: dark` block removed | Judges may be on any device; one deterministic palette means the status colours (green/amber/blue/purple/grey) always read correctly, and screenshots match the video. |
| D-06 | `asOfDate` is frozen to the **upload timestamp**, stored on the result, and reused for every re-run of that dataset | Rules must be pure and reproducible. If `asOfDate` drifted between runs, reservation deadlines and onboarding dates would change without an input change, breaking the determinism test. |
| D-07 | The engine runs **client-side**; the only server route is the AI proxy | Decisions must not depend on the network, and the Gemini key must never reach the browser. |
| D-08 | Scores are computed and **rounded to integers** at component level, summed without further rounding | Keeps the breakdown arithmetic visible and exactly additive on the decision card. |
| D-09 | Rank tie-break chain ends at Application ID ascending, string-compared | The spec names it as the final tie-break; a string compare is stable across locales when using an explicit `<`/`>` rather than `localeCompare`. |
| D-10 | Duplicate Application IDs: the **first** row in sheet order is the live applicant; later rows are held ON HOLD and excluded from allocation | The spec says "second and later rows held for confirmation, excluded from allocation". Sheet order is used rather than any quality ordering so the behaviour is predictable to the operator reading their own file. |
| D-11 | Held duplicate rows get a synthetic internal key (`APP-023#2`) for React keys and routing, while still displaying their original ID | Two rows cannot share a URL. The displayed ID is untouched. |
| D-12 | `REDIRECTED` applicants are ranked and traced like everyone else but consume no capacity and reserve no pin | The spec calls them advisory; ranking them anyway keeps the trace complete and lets the card explain who beat them. |
| D-13 | Partner tokens are a deterministic hash of `applicationId + datasetHash`, not random | A random token would break the determinism test and would change on every re-run, invalidating links the manager had already sent. |
| D-14 | "not stated" is rendered by a single `<NotStated/>` component wherever a normalised value is `null` | One place to enforce the never-invent-a-fact rule, and one thing to grep for when auditing it. |
| D-15 | The AI cache key is `SHA-256({callType, model, input})` and is held both in a module-level `Map` and in `localStorage` | Memory cache survives a page's lifetime, localStorage survives reload; both are keyed identically so a reload is a cache hit, not a new spend. |
| D-16 | Cost ledger prices are a constant table in `lib/ai/pricing.ts`, labelled as an estimate | Gemini does not return a price; the estimate must be clearly an estimate rather than implied truth. |
| D-17 | Feature switches are encoded in the share URL as a single base36 bitfield (`?f=`) | Short enough to paste into WhatsApp, and order-stable so the same configuration always produces the same link. |
| D-18 | `?safe=1` is read **before** React hydration in the store initialiser | It must disable persistence before any localStorage read can throw, which is the failure it exists to survive. |
| D-19 | The processed-workbook export is generated client-side with SheetJS | No server round trip means the export works on the free Vercel tier, offline, and in safe mode. |
| D-20 | Tests run under Vitest with the `node` environment; no component tests | The spec's acceptance list is entirely engine, parser, chat-router and fail-safe behaviour — all pure functions. Component rendering is verified by the scripted journey in `JUDGE_TEST_PLAN.md`. |
| D-21 | **Seed adjustment.** TER-08 open slots raised from the brief's `1` to `2` | With one slot only the higher-ranked APP-013 could take a 45-day reservation, and case 7 needs APP-012 to hold one too. Both of TER-08's free pins can physically take a store, so `2` is the honest figure. The rule was not touched. |
| D-22 | **Seed adjustment.** APP-025 investment raised from the brief's `18` lakh to `20` lakh, the Tier 2 minimum | At 18 the investment check R-01 failed first and masked R-04, the undersized 340 sq ft shop this row exists to demonstrate. Raising investment to exactly the minimum lets the intended rule fire. The rule was not touched. |
| D-23 | When several gates fail, the one with the **most final** outcome wins — reject beats hold beats redirect — rather than the first in evaluation order | APP-026's pin holds an existing store (G-03, redirect) *and* sits in a city with no territory at all (G-04, reject). A redirect is only meaningful if somewhere exists to redirect to, and the reject proves there is not, so first-wins would have given advice that cannot be followed. |
| D-24 | A gate redirect (G-03/G-04) suggests pins that are merely **free**; Pass B's cross-city relocation additionally requires a **free slot** | Spec §5.7 applies the capacity condition only to the relocation branch. The distinction is real: a relocated applicant is competing for capacity, whereas a redirected one is being told where they could apply instead — advice, not a claim on a slot. |
| D-25 | Reason sentences never contain rule codes; the codes live in the rule trace behind the decision card | R-05 originally rendered "1 blocking data-quality issue: DQ-13", which is meaningless to the operator the sentence is written for. It now carries the issue's own plain-English message. |
